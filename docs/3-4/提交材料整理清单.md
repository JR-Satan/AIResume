# 软件工程课设提交材料整理清单

根据要求“提交软件设计说明及用户手册各一册，内部章节进行小组区分”，最终建议提交两本统一文档，而不是每个小组各交一份零散文档。

## 1. 最终必须提交的两册材料

### 1.1 软件设计说明书

用途：说明系统为什么这样设计、各模块怎么协作、数据如何流转、接口如何约定、关键技术如何实现。

建议文件名：

```text
智能求职模拟平台-软件设计说明书.docx
```

内部按小组分章节，例如：

```text
第 1 章 项目概述
第 2 章 总体架构设计
第 3 章 3-1 简历新建编辑组设计
第 4 章 3-2 自动识别导入组设计
第 5 章 3-3 用户模板管理组设计
第 6 章 3-4 大模型润色组设计
第 7 章 3-5 模拟面试及职位推送组设计
第 8 章 跨组接口与数据流
第 9 章 部署、测试与风险控制
```

### 1.2 用户手册

用途：告诉用户怎么安装、启动、配置和使用系统功能，偏操作说明，不写太多内部代码细节。

建议文件名：

```text
智能求职模拟平台-用户手册.docx
```

内部按功能模块分章节，例如：

```text
第 1 章 系统简介与运行环境
第 2 章 安装与启动
第 3 章 账号、模板与基础配置
第 4 章 简历新建与编辑使用说明
第 5 章 图片/PDF 简历导入使用说明
第 6 章 模板市场与简历版本管理使用说明
第 7 章 AI 润色、质量评分与结构诊断使用说明
第 8 章 模拟面试与岗位推荐使用说明
第 9 章 常见问题与异常处理
```

## 2. 各小组需要交给总负责人汇总的内容

每个小组建议提交以下材料片段，方便统一排版到两册文档：

```text
1. 本组功能简介
2. 本组功能流程图或模块图
3. 本组核心数据结构
4. 本组接口说明
5. 本组关键实现说明
6. 本组测试与验收说明
7. 本组用户操作说明
8. 本组常见问题
```

其中：

- `1-6` 主要进入《软件设计说明书》。
- `7-8` 主要进入《用户手册》。

## 3. 3-4 组需要提交的章节材料

### 3.1 放入软件设计说明书的内容

章节标题建议：

```text
第 6 章 3-4 大模型润色组设计
```

建议包含：

```text
6.1 模块职责
说明 3-4 组负责简历质量评分、岗位结构诊断、全文润色、字段级建议和 TextGrad 可视化。

6.2 功能结构
说明质量评分、岗位结构建议、全文润色、单字段润色、AI 调用重试、安全回写之间的关系。

6.3 数据输入与输出
输入包括结构化简历快照、目标岗位、字段路径、原字段文本。
输出包括评分结果、结构建议、润色操作、字段级建议、TextGrad 优化轨迹。

6.4 核心流程设计
说明 Forward 候选生成、Textual Gradient 反馈、Optimizer 优化结果、安全校验、用户确认回写。

6.5 评分稳定性设计
说明评分低温度、评分锚点、评分区间展示、同一简历缓存复用。

6.6 字段级安全回写设计
说明 fieldPath 白名单、oldValue 校验、用户确认后写回、避免覆盖用户手动编辑。

6.7 AI 调用稳定性设计
说明首次错误静默重试，连续两次失败才向用户报错。

6.8 与其他小组接口
说明与 3-1 的字段编辑接口、与 3-2 的 OCR 导入数据、与 3-3 的版本保存、与 3-5 的岗位与面试建议数据对接。

6.9 测试与验收
说明构建测试、评分测试、润色结果 JSON 合规测试、字段回写测试、异常调用测试。
```

可参考已有文件：

```text
3-4大模型润色组-软件需求规格说明书.docx
3-4大模型润色模块需求规格分析（仅功能规格）.docx
3-4大模型润色组项目说明文档.docx
3-4README.md

```

### 3.2 放入用户手册的内容

章节标题建议：

```text
第 7 章 AI 润色、质量评分与结构诊断使用说明
```

建议包含：

```text
7.1 功能入口
说明进入简历编辑页后，在 3-4 大模型润色面板中使用相关功能。

7.2 API 配置
说明进入网站配置页，填写模型名称、API URL 和 API Key。

7.3 目标岗位设置
说明用户可以输入目标岗位方向，系统会据此进行评分、结构诊断和润色。

7.4 质量评分
说明点击质量评分后，全屏查看综合质量区间、四维评分、总体意见和字段级建议。

7.5 岗位结构建议
说明点击岗位结构建议后，查看模块顺序、经历取舍、内容补充和风险提醒。

7.6 全文润色
说明点击全文润色后，左侧显示原简历，右侧显示修改后简历，中间显示每处修改卡片。

7.7 查看修改详情
说明点击中间修改卡片后，可展开查看原文、改后文本、修改理由，左右两侧同步高亮对应字段。

7.8 应用润色结果
说明用户可以应用单条修改，也可以一键应用全部修改。只有用户确认后才会写回简历。

7.9 常见问题
说明 API Key 错误、模型无响应、未返回可应用操作、评分缓存复用等问题。
```

## 5. 汇总排版建议

两册文档建议统一格式：

- 封面包含课程名称、项目名称、班级、小组成员、提交日期。
- 正文使用统一标题层级。
- 各小组章节标题统一写成“3-1 / 3-2 / 3-3 / 3-4 / 3-5 + 小组名称”。
- 图表统一编号，例如“图 6-1 3-4 大模型润色流程图”。
- 接口表统一包含：接口名称、调用方、提供方、输入、输出、作用说明。
- 用户手册每个功能建议配 1-2 张界面截图。
