# 3-4 大模型润色组合并说明

本文件夹是 3-4 组用于跨组合并的代码交付包。各小组项目都基于同一前端工程修改，因此本包按原项目路径整理了 3-4 功能相关源码，便于直接复制、对照比较或人工合并。

## 1. 合并目标

合并后目标项目应具备以下能力：

- 在简历编辑页提供 3-4 大模型润色面板。
- 支持目标岗位输入、质量评分、岗位结构建议、全文润色。
- 支持 TextGrad 风格的候选生成、文本反馈、优化结果展示。
- 支持左右完整简历对比、中间润色操作卡片、点击操作后联动高亮。
- 支持评分缓存、低随机性评分、评分区间展示和评分锚点。
- 支持 AI 调用失败时后台静默重试一次，连续两次失败才向页面报错。
- 支持 DeepSeek / OpenAI 兼容接口配置。
- 3-4 相关 UI 已加入“3-4 大模型润色组”半透明水印，便于跨组合并和演示时区分模块归属。

## 3. 核心文件清单

### 3.1 3-4 必需新增/修改文件

这些文件是 3-4 功能主体，建议完整合并：

```text

src/services/promptOptimizationService.ts
src/data/promptOptimizationExamples.ts
src/types/promptOptimization.ts
```

作用说明：

- `promptOptimizationExamples.ts`：提示词优化样例集。
- `promptOptimization.ts`：提示词优化相关类型。
- `ResumeAIPanel.vue`：3-4 组在简历编辑页的主 UI。

## 4. 推荐合并顺序

建议按以下顺序合并，能减少类型错误和路径缺失：

1. 合并类型文件：

```text
src/types/resume.d.ts
src/types/promptOptimization.ts
```

2. 合并底层 AI 调用与配置：

```text
src/api/qwenAPI.ts
src/worker/workerPool.ts
src/worker/aiWorker.ts
src/store/useSettingsStore.ts
src/views/setting/index.vue
vite.config.ts
.env
.env.production
.env.local.example
```

3. 合并 Store 能力：

```text
src/store/useResumeStore.ts
```

重点确认目标项目中是否已有其他组新增的 store 字段或方法。合并时保留其他组已有逻辑，再加入以下 3-4 方法：

```ts
getResumeSnapshot()
getFieldValue(fieldPath)
applyPolishOperations(operations)
```

4. 合并 3-4 服务层：

```text
src/services/aiPolishService.ts
src/services/promptSets.ts
src/services/promptOptimizationService.ts
src/data/promptOptimizationExamples.ts
```

5. 合并页面入口和字段入口：

```text

src/views/resume/components/ResumeAIPanel.vue
src/views/resume/components/AIEnhancePopover.vue
src/views/resume/components/workExperience.vue
```

## 5. 容易冲突的地方

### 5.1 `src/store/useResumeStore.ts`

可能和 3-1、3-2、3-3 的数据保存、导入、版本管理逻辑冲突。

合并原则：

- 保留其他组已有的数据字段和 action。
- 补充 3-4 的简历快照读取方法。
- 补充 3-4 的字段级安全回写方法。
- 不要删除其他组的导入、保存、模板或版本管理方法。

### 5.2 `src/types/resume.d.ts`

可能和其他组扩展的简历类型冲突。

合并原则：

- 其他组已有字段全部保留。
- 新增 3-4 类型时避免改名。
- `ResumeContentSnapshot` 应只包含简历内容，不应包含展示配置或运行状态。

### 5.3 `src/views/resume/index.vue`

可能和 3-1 编辑器布局、3-2 导入入口、3-3 模板入口冲突。

合并原则：

- 只需要在页面合适位置插入：

```vue
<ResumeAIPanel />
```

- 并加入导入语句：

```ts
import ResumeAIPanel from './components/ResumeAIPanel.vue';
```

### 5.4 字段组件

涉及文件：

```text
workExperience.vue
project.vue
selfEvaluation.vue
honor.vue
```

合并重点不是 UI 样式，而是给 `AIEnhancePopover` 传入：

```vue
fieldPath
originalText
```

这些字段路径必须和 `aiPolishService.ts` 中允许回写的白名单一致。

### 5.5 顶部导航和个人信息

`Header/index.vue`、`personalInfo.vue` 属于体验优化，不是 3-4 服务必需。如果其他组已经负责这些页面，建议人工确认后再合并。

当前默认模型：

```text
deepseek-v4-pro
```

本地开发默认接口：

```text
/deepseek-api/chat/completions
```

生产环境默认接口：

```text
https://api.deepseek.com/chat/completions
```

本包只提供 `.env.local.example`，不包含真实 API Key。

本地运行时请在目标项目根目录创建 `.env.local`：

```text

```

注意：

- 不要把真实 `.env.local` 提交到仓库。
- 如果正式部署，建议由后端代理保存 Key，前端不要直接暴露 Key。

## 7. 已加入的稳定性处理

### 7.1 AI 调用错误重试

位置：

```text
src/services/aiPolishService.ts
```

规则：

- 第一次 AI 调用失败时，后台自动静默重试一次。
- 第二次仍失败，才向页面返回错误。

### 7.2 评分稳定性

位置：

```text
src/services/aiPolishService.ts
src/services/promptSets.ts
src/views/resume/components/ResumeAIPanel.vue
```

规则：

- 质量评分调用使用 `temperature: 0`。
- 同一简历内容、同一目标岗位、同一 PromptSet 版本会复用评分缓存。
- 页面展示质量区间，例如 `85-89（优秀）`，减少单次整数分的偶然性影响。
- 提示词内加入评分锚点，约束不同分数段的含义。

### 7.3 字段级安全回写

位置：

```text
src/store/useResumeStore.ts
src/services/aiPolishService.ts
```

规则：

- AI 只能回写白名单字段。
- 回写前检查当前字段值是否仍等于 AI 调用时的旧值。
- 如果用户已经手动修改该字段，则跳过 AI 回写，避免覆盖用户新输入。

## 8. 合并后验证

合并完成后在目标项目根目录执行：

```bash
npm install
npm run build
```

如需本地演示：

```bash
npm run dev
```

进入简历编辑页后建议验证：

- 页面顶部或编辑区中能看到 3-4 大模型润色面板。
- 输入目标岗位后点击“质量评分”，能打开全屏评分报告。
- 点击“岗位结构建议”，能输出模块顺序、经历取舍、内容补充建议。
- 点击“全文润色”，能看到左右完整简历对比和中间修改卡片。
- 点击中间卡片时，左右两侧对应字段能高亮。
- 应用润色后，字段内容能正确写回。
- 连续点击同一份简历评分时，应提示复用缓存，而不是重复调用模型。

## 10. 对其他小组的建议

- 3-1：保留字段路径 `fieldPath` 规范，便于 3-4 建议定位到具体字段。
- 3-2：OCR 导入后只需要更新结构化简历数据，不建议导入完成后自动触发润色。
- 3-3：保存简历版本时可附带 3-4 的评分结果、结构建议摘要和润色来源标记。
- 3-5：岗位推荐和模拟面试可以读取 3-4 评分建议、目标岗位和结构诊断结果，但不要直接覆盖简历正文。
